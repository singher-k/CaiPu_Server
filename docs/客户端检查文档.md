# 用户信息更新接口 - 客户端排查文档

## 接口信息

- **接口地址**: `http://120.55.4.95:3000/api/user/update`
- **请求方式**: `POST`
- **Content-Type**: `application/json`

## 请求参数说明

### 必填参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | 数值/字符串 | ✅ 是 | 用户ID，登录时服务端返回的id字段 |

### 可选参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| nickName | 字符串 | ❌ 否 | 用户昵称，至少提供nickName或avatarUrl中的一个 |
| avatarUrl | 字符串 | ❌ 否 | 用户头像URL，至少提供nickName或avatarUrl中的一个 |

### 完整请求示例

```json
POST http://120.55.4.95:3000:3000/api/user/update
Content-Type: application/json

{
  "userId": 1,
  "nickName": "新昵称",
  "avatarUrl": "https://example.com/avatar.jpg"
}
```

## 常见错误排查

### 错误1: HTTP 400 - "请求参数错误"

**原因**: 请求参数不符合服务端验证要求

**排查步骤**:

1. **检查userId是否存在**
   ```javascript
   // 错误示例 - userId为空
   { "nickName": "新昵称" }

   // 正确示例
   { "userId": 1, "nickName": "新昵称" }
   ```

2. **检查是否提供了有效的更新字段**
   ```javascript
   // 错误示例 - 只提供了userId，没有提供nickName或avatarUrl
   { "userId": 1 }

   // 正确示例 - 提供userId和至少一个更新字段
   { "userId": 1, "nickName": "新昵称" }

   // 正确示例 - 只更新头像
   { "userId": 1, "avatarUrl": "https://example.com/avatar.jpg" }

   // 正确示例 - 两个字段都更新
   { "userId": 1, "nickName": "新昵称", "avatarUrl": "https://example.com/avatar.jpg" }
   ```

3. **检查Content-Type是否正确**
   ```javascript
   // 错误示例 - 使用form-urlencoded格式
   userId=1&nickName=新昵称

   // 正确示例 - 使用JSON格式
   // Header: Content-Type: application/json
   // Body: {"userId":1,"nickName":"新昵称"}
   ```

### 错误2: 参数类型不匹配

**userId必须是数值或字符串形式的数字**

```javascript
// 正确示例 - 数值类型
{ "userId": 1, "nickName": "新昵称" }

// 正确示例 - 字符串类型
{ "userId": "1", "nickName": "新昵称" }

// 错误示例 - userId为undefined或null
{ "userId": undefined, "nickName": "新昵称" }
{ "userId": null, "nickName": "新昵称" }
```

### 错误3: 登录后未保存userId

客户端需要从登录接口响应中获取userId：

```javascript
// 登录接口响应示例
{
  "success": true,
  "user": {
    "id": 1,          // <-- 这个就是userId
    "openid": "xxx",
    "nickName": "微信用户",
    "avatarUrl": ""
  },
  "sessionKey": "xxx"
}

// 正确的调用方式
const loginRes = await requestLogin();
const userId = loginRes.user.id;  // 获取userId

// 然后使用userId调用更新接口
await updateUserProfile({
  userId: userId,
  nickName: "新昵称"
});
```

## 客户端代码示例

### 正确写法

```javascript
/**
 * 更新用户信息
 * @param {Object} params - 参数
 * @param {number|string} params.userId - 用户ID（必填）
 * @param {string} params.nickName - 用户昵称（选填）
 * @param {string} params.avatarUrl - 头像URL（选填）
 */
async function updateUserProfile(params) {
  const { userId, nickName, avatarUrl } = params;

  // 参数校验
  if (!userId) {
    console.error('❌ userId不能为空');
    return { success: false, message: 'userId不能为空' };
  }

  if (!nickName && !avatarUrl) {
    console.error('❌ 至少提供一个要更新的字段');
    return { success: false, message: '请提供要更新的用户信息' };
  }

  try {
    const response = await new Promise((resolve, reject) => {
      wx.request({
        url: 'http://120.55.4.95:3000/api/user/update',
        method: 'POST',
        header: {
          'Content-Type': 'application/json'
        },
        data: {
          userId: userId,
          nickName: nickName || '',
          avatarUrl: avatarUrl || ''
        },
        success: (res) => {
          console.log('✅ 更新成功:', res.data);
          resolve(res);
        },
        fail: (err) => {
          console.error('❌ 请求失败:', err);
          reject(err);
        }
      });
    });

    return response.data;
  } catch (error) {
    console.error('❌ 更新用户信息失败:', error);
    return { success: false, message: error.errMsg || '网络请求失败' };
  }
}

// 调用示例
updateUserProfile({
  userId: 1,
  nickName: '新昵称',
  avatarUrl: 'https://example.com/avatar.jpg'
});
```

### 错误写法

```javascript
// 错误1: 忘记传递userId
updateUserProfile({
  nickName: '新昵称'
});

// 错误2: 没有传递任何更新字段
updateUserProfile({
  userId: 1
});

// 错误3: Content-Type设置错误
wx.request({
  url: 'http://120.55.4.95:3000/api/user/update',
  method: 'POST',
  header: {
    'Content-Type': 'application/x-www-form-urlencoded'  // 错误！
  },
  data: {
    userId: 1,
    nickName: '新昵称'
  }
});

// 错误4: 请求参数未序列化
wx.request({
  url: 'http://120.55.4.95:3000/api/user/update?userId=1&nickName=新昵称',  // GET方式
  method: 'POST'  // 矛盾
});
```

## 服务端验证逻辑

服务端代码验证顺序：

```
1. 检查userId是否存在
   ↓ 如果不存在
   返回 400: "用户ID不能为空"

2. 检查是否提供了nickName或avatarUrl
   ↓ 如果都没有提供
   返回 400: "请提供要更新的用户信息"

3. 查询数据库中的用户
   ↓ 如果用户不存在
   返回 404: "用户不存在"

4. 执行更新操作
   ↓ 如果成功
   返回 200: {"success": true, "message": "用户信息更新成功", ...}
```

## 常见问题

**Q: 返回400错误，但是参数看起来都对？**

A: 请检查：
1. 控制台日志中 `userId` 的实际值，可能是 `undefined`
2. JSON序列化是否正确，特别是包含中文时
3. 网络请求是否被拦截或修改

**Q: 需要同时传nickName和avatarUrl吗？**

A: 不需要，只需要传至少一个。如果只更新头像，只传 `avatarUrl` 即可；如果只更新昵称，只传 `nickName` 即可。

**Q: userId从哪获取？**

A: 从登录接口的响应中获取。登录成功后会返回 `user.id`，请将这个值保存到本地存储（如wx.setStorageSync）中，在需要时读取使用。
